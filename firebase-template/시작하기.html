내 계정에 예약 사이트 설치하기

이 ZIP에는 선택한 구성과 실행 코드, 데이터 접근 규칙, 배포 설정이 들어 있습니다. 기존 서비스는 사용하지 않습니다.

ZIP을 Firebase 화면에 올리는 방식은 아닙니다. Firebase 최초 설정과 배포 도구 실행이 필요합니다. 유료 서비스·이메일·문자 발송은 포함하지 않습니다. 본인 새 테스트 프로젝트에서 설치·동시 신청·권한 검사를 완료한 뒤 실제 예약을 받으세요.

1. 본인 Firebase 프로젝트 만들기

Firebase 콘솔에서 새 프로젝트를 만들고 무료 Spark 요금제로 시작합니다. 기존 운영 프로젝트를 선택하지 마세요. Analytics는 필수가 아닙니다.

프로젝트 설정 → 내 앱에서 웹 앱을 추가합니다. Hosting과 Firestore를 사용할 예정입니다.

2. 데이터베이스·로그인 준비

Firestore Database → 데이터베이스 만들기. 지역은 학교의 정책과 운영 환경에 맞게 선택하세요. 보안은 테스트 모드 공개 상태로 두지 않습니다. 이 패키지의 규칙을 배포합니다.

Authentication → 시작하기 → 로그인 방법에서 익명, 이메일/비밀번호를 활성화합니다. 익명 인증은 신청자가 로그인 화면 없이 요청하도록 사용합니다.

Authentication → 사용자 추가에서 본인 관리자 이메일·비밀번호를 생성합니다. 비밀번호는 Firebase에만 입력하세요. 생성된 사용자 UID를 복사합니다.

Firestore → 데이터에서 admins 컬렉션을 만들고, 문서 ID를 관리자 UID로 정합니다. 필드 enabled를 boolean true로 넣습니다. 이 문서는 사이트에서 추가·수정할 수 없도록 막혀 있습니다.

3. 배포 도구 설치

Node.js LTS를 설치합니다. 다운로드한 폴더의 주소 표시줄에 powershell을 입력해 터미널을 엽니다. macOS는 해당 폴더에서 터미널을 엽니다.

npm install -g firebase-tools
npm run configure

Firebase 웹 앱 설정의 공개 값(apiKey, authDomain, projectId, appId 등)을 그대로 복사해 붙여넣습니다. 마지막 빈 줄에서 Enter를 한 번 더 누르면 저장합니다. Firebase의 apiKey는 웹 공개 설정이며 관리자 비밀 키가 아닙니다. 서비스 계정 JSON이나 개인 키를 넣지 마세요. 콘솔에서 SDK 설정 및 구성 → 구성을 선택하고 코드 상자의 복사 아이콘을 사용합니다. const firebaseConfig =, 줄바꿈, 따옴표를 직접 수정할 필요가 없습니다. 공개 설정 저장 완료와 배포 대상이 표시되면 대상이 본인의 프로젝트 ID인지 확인하세요.

이 단계는 파일 준비만 하며 연결·배포 성공을 뜻하지 않습니다.

4. 본인 계정에 배포

firebase login
npm run deploy

본인 Google 계정으로 로그인합니다. .firebaserc에 기록된 프로젝트 ID가 본인 새 프로젝트인지 확인하세요. 규칙과 Hosting을 함께 배포합니다. Firestore 생성 전이면 배포가 실패합니다.

CLI가 출력하는 Hosting 주소를 엽니다. 연결 오류가 나면 공개 설정·Authentication 활성화·배포 로그를 확인하세요. 실패한 상태를 설치 완료로 간주하지 않습니다.

5. 최초 관리자 초기화

사이트에서 관리자 이메일·비밀번호로 로그인하고 선택한 구성으로 초기 자료 만들기를 누릅니다. 도우미에서 만든 날짜·시간표·정원·물품별 수량·신청 항목을 자신의 Firestore에 저장합니다. 이미 초기화된 자료를 덮어쓰지 않습니다.

예약 확인 코드는 48자리 비밀 코드입니다. 이를 아는 사람은 해당 예약을 조회·기한 내 취소할 수 있습니다. URL·공개 문서·공유 화면에 노출하지 마세요. 분실하면 관리자가 확인 후 도와주어야 합니다.

6. 실제 접수 전 확인

  • 브라우저 두 개에서 마지막 한 자리를 신청해 정확히 한 건만 확정되는지 확인합니다.
  • 물품 잔여 수량 초과 신청이 거절되고 취소·거절·반납 시 수량이 복구되는지 확인합니다.
  • 관리자 로그아웃 후 예약 전체 목록과 관리자 저장이 거부되는지 확인합니다.
  • 신청 기간 밖·지난 회차·취소 기한 밖 요청이 거부되는지 확인합니다.
  • 예약 수보다 적은 정원·재고로 바꾸기와 예약 기록 삭제가 차단되는지 확인합니다.
  • 신청 전·중·후 안내와 필수·숫자·드롭다운 항목을 확인합니다.
  • 월별 예약 백업을 내려받아 보관·삭제 기준을 정합니다. 수동 백업 파일도 개인정보이므로 보호하세요.

무료 사용량·익명 인증 생성 제한·동시 처리 한도가 있습니다. 500명 접속과 한 회차 10~20명 동시 신청 성능은 실제 프로젝트에서 부하 시험해야 합니다. 무제한·무장애를 보장하지 않습니다.

현재 기능 범위와 운영 제약

신청자 예약·조회·취소, 월별 달력, 날짜/시간/교시, 물품별 수량, 관리자 승인·거절·취소·일정 변경·대여·반납, 월별 예약 조회·검색·CSV·백업, 회차 정원·중지, 운영일 추가, 신청 전·중·후 문구를 포함합니다.

메일·문자·Sheets 자동 연결·다중 교시 한 번에 예약·재고 공유 범위 변경·기존 서버 자동 이전은 포함하지 않습니다. 물품 수량은 겹치지 않는 회차별로 관리하므로 패키지 생성 시 겹치는 회차를 거부합니다. 관리자에서 수정하는 보유 수량은 선택한 회차에 적용됩니다. 교시·날짜 식별자 변경은 기존 예약을 유지하기 위해 제한합니다.

코드 검사는 실제 Firebase 프로젝트에서의 동작 확인과 다릅니다. 보안 규칙과 성능 검증 결과는 검증상태.md를 확인하세요.
